# 遥控器音频写入失败 · 2026-10-28

本机 RcHarness 的 CoreAudio 日志显示，新引擎启动后 20–30 ms 收到
`iounit configuration changed > stopping the engine`，随后 `engine.isRunning`
变为 false，首批 PCM 写入即报“无法写入遥控器音频”。启动过程中可见默认输出
44.1 kHz 与虚拟麦克风 48 kHz 的格式切换。驱动环形缓冲拒绝写入和权限不足并非这次
捕获到的触发原因。

旧代码安全结束整段会话，只在下一次语音键按下时新建图；直接重启旧播放器则曾在
`AVAudioPlayerNode.play()` 处触发 Objective-C 异常（本机 2026-10-27 崩溃报告）。

## 修复

- 选定设备后等待 100 ms 再准备、启动引擎；等待期间缓存语音，保持队列上限。
- 配置变化通知转到主队列处理，每段会话最多重建两次全新播放图。
- 重建期间保留尚未确认播放完成的 PCM，继续接收 BLE 数据；旧图回调不会计入已播样本。
- 排空、取消和超时仍负责释放语音键；取消会清除延迟启动和重建任务。

恢复采用完整 buffer 重放，发生在 buffer 中间的中断可能重复该 buffer 已播放的片段；
不承诺逐样本无缝恢复。持续设备故障仍会明确报错并结束会话。

## 验证

`swift test` 覆盖中断时重放、重建期间继续收包、没有新数据时恢复尾音、旧回调隔离、
重试上限、取消重建、延迟启动和空会话排空。

真实 HAL 测试需要已安装的 RcHarness 麦克风和已有录音授权，未满足时以退出码 2
跳过，不主动请求权限。测试只向虚拟设备写入合成静音，不采集麦克风、不切换系统默认设备。

```sh
# 回放旧版启动时序，作为本机故障对照（预期可能失败）。
bash scripts/test_audio_output.sh --original
# 通过当前实现发送静音，断言每次的播放样本数和最终状态。
bash scripts/test_audio_output.sh
```

本机同一驱动下的对照结果：旧时序 12 段失败 8 段，当前实现 12 段全部完成，
每段确认播放 1600 个样本。此结果覆盖引擎启动故障，不代表已完成遥控器硬件采音、
睡眠唤醒或第三方语音应用的完整兼容性验收。
