# 首次语音触发后没有文字 · 2026-11-04

故障表现为偶尔能唤起语音输入浮窗，但没有识别文字。一段故障会话的诊断计数显示：HID press 与 Fn down 之间约有 3 秒间隔；BLE 会话收到 176 包、42,240 个 16 kHz 采样（约 2.64 秒），输出只播放 8,000 个、丢弃 34,240 个。后续会话未记录同类丢弃。日志不包含实际音频或识别文字，不能据此证明所有无文字事件都是同一个原因。

用同样的 176 × 240 采样数量、延迟准备回调重放控制器到真实输出状态机的调用，旧实现稳定失败：积压被半秒上限裁剪，第一包从序号 1 变成序号 143。命令为 `swift test --filter VoiceSessionTests/testColdOutputPreparationRetainsTheCapturedFirstUtterance`。注入引擎工厂的检查同时确认，旧实现会在调用线程构造 AVAudioEngine；主队列调用时会阻塞语音键触发。真实 HAL 探针在本轮修复前 12/12 通过，begin 同步耗时 10–27 ms，未现场重现那次约 3 秒阻塞，故不把底层 CoreAudio 当时阻塞的具体原因写为已证实。

修复将 AVFoundation 对象创建移至专用串行队列，准备中的取消不等待该队列；准备图从未投递音频，延后清理不清空新会话的 HAL 缓冲。已启动图仍在切换前完成停止及清空。输出状态机为启动期间及其追赶阶段保留有界的 80,000 采样容量，追平后回到 8,000 采样实时上限；准备 5 秒超时或启动队列超限会明确报错。排空预算包含待播音频长度，避免保留首句后又被旧的一秒超时截断。定时通过注入 Scheduler 和 TestClock 验证。

回归覆盖完整首句及包顺序、追赶期间的新包、长句排空、准备超时、容量超限、取消后的迟到准备回调，以及后台创建和取消中的健康查询。自动化不会向真实会话发送 Fn，也不采集语音或断言输入法识别结果。

本轮 `scripts/test_all.sh` 通过：161 项 Swift 测试、HAL ASan/UBSan、Objective-C 异常边界和 12/12 次真实 HAL 静音输出。未采集或验证用户实际听写内容。

使用固定证书签名、安装并重启修复版后，实测确认测试环境中的唤起和识别已恢复；尚不据此推断长时间空闲、睡眠唤醒或其他输入法的全部场景。
