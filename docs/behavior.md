# RcHarness 行为说明

README 只保留概览；本文记录界面与运行时的具体行为，便于验收和排查。

## 设置页面

界面参考 [remote-mic-app](https://github.com/HD838A/remote-mic-app/tree/0c3363a3edacec62186b94775882fbfc54368028) 的页面结构，以 RcHarness 自己的 SwiftUI 视图和设备链路实现，移除“回眸”及其相关记录和 Agent 入口。

右侧主工作区延伸至窗口顶部，与透明标题栏融为一体；左上角保留 macOS 窗口控制按钮和原生标题栏拖动区域。

“启用遥控器映射”等共用样式的开关在按压及切换时，左侧文字保持原有明暗；开关自身显示开关状态。点击文字或开关均可切换，键盘与辅助功能操作沿用原有行为。

主工作区页面边距统一为 24 pt，页面标题使用 24 pt 半粗体。普通面板与表单图标、设备卡的底色和边框采用中性色；强调色用于选中状态和操作入口，连接及权限状态保留语义颜色。常用语编辑器的标题、正文标签和列表排序提示均不小于 11 pt。

设置页的重复样式集中在 `Sources/RcHarness/SettingsStyle.swift`：页面边距 24 pt，组内间距 8／12 pt，组间间距 16／24 pt，默认面板内边距 20 pt、圆角 16 pt，普通自绘控件圆角 8 pt，常规／紧凑控件内边距 12／8 pt。页面标题、面板标题、弹窗标题、正文及说明文字使用共享字体层级；特殊图标、等宽数值和缩放内容保留各自尺寸。保留 108 pt 导航轨道、原生控件、紧凑弹出选择器及列表滚动条的原生布局；遥控器标定、连线、点击区域和五向圆盘几何不套用统一网格。

设置页从应用信息卡开始展示，下方依次为全局按键、权限、通用设置及诊断与支持；配置导入导出和主题模式可在通用设置中调整。

删除常用语或组合动作前，统计所有已保存遥控器型号中各方案及全局按键的直接引用，并追踪嵌套组合动作带来的间接影响。存在引用或五向分配时先显示确认面板，按型号和方案列出受影响映射数量、相关组合动作与待解除的五向位置；取消不修改配置。确认时重新统计，影响范围或名称变化后需核对最新信息再次确认。普通按键和组合动作步骤保留被删 ID，继续在编辑器提示失效，不自动清空；常用语五向分配在明确告知后解除。

未被引用的常用语、组合动作及允许删除的未绑定自定义方案直接删除，并在工作区底部持续显示“撤销删除”入口；被引用对象确认删除后也有同样入口。撤销按删除的逆序恢复完整对象、原手动顺序及其五向分配，方案在原型号中恢复，切换型号后也可撤销；原方案被选中且当前仍停留在默认回退方案时恢复原选择。删除后其他编辑和新建内容保持不变；如原五向位置被重新分配，或组合动作／方案发生 ID、名称冲突，撤销提示处理冲突后重试，不覆盖新内容。删除及撤销各使用一次完整配置提交，保存失败不部分生效，也不丢弃撤销记录；导入前备份保持不变。

删除撤销记录在本次运行期间有效，可连续撤销且不会随普通提示自动消失；关闭撤销提示会清空本次删除撤销记录，成功导入或恢复配置也会清空，以免旧撤销污染新配置。默认方案、内置方案与仍绑定 Harness 的方案继续禁止删除。

配置导入分为文件校验、预览和确认替换三个步骤。选择文件后仅在内存解码、校验并迁移名称和旧版结构，不修改当前配置；预览显示遥控器配置（含全局按键）、方案、Harness 应用和绑定、组合动作、常用语及五向分配的当前数量与导入后数量，失效引用和方案名称修复一并提示。旧版备份归入当前遥控器，其他型号恢复默认配置；版本 4 按型号恢复。点击“替换配置”后才提交，取消或关闭预览不改变配置；文件无法读取、格式或版本不支持、组合动作／常用语／步骤 ID 重复等校验失败时不写入任何配置。预览保留已校验的数据，之后修改源文件不影响确认内容；更换遥控器后立即关闭导入或恢复预览；即使再切回原型号，旧预览也不能确认，需重新选择文件或重新发起恢复。导入和导出使用的系统文件面板跟随 macOS 当前语言显示，无匹配本地化时回退到简体中文。

每次替换前自动保留一份当前配置，与新配置一起编码为单份设置快照，一次提交；无法保存配置或备份时维持原状态。内存更新期间不逐项写入偏好设置，完成后统一通知映射、语音触发和 Harness 使用方。后续编辑继续使用该快照，旧版分散存储仅作为迁移读取来源。外观、启动选项、音频设置与使用统计不属于导入范围。

“恢复替换前配置”位于配置导入导出旁，未发生替换时不可用；备份包含各遥控器的方案、全局按键、绑定与选择状态，以及共用的组合动作、常用语及五向分配，重启后仍保留。恢复前同样显示范围摘要并要求确认；取消恢复不改变配置或备份。恢复操作也保存被替换的当前配置，因此可以撤回这次恢复。每次只保留最近一份替换前备份，新一次成功替换会更新它。

连接与语音页右上角与其他设置页面共用遥控器信息卡，显示当前型号、连接状态，并在已连接且读取到电量时显示电量。已连接时，状态圆点和“已连接”文字均显示绿色；未连接时使用次要文字色。整张卡片可点击，右侧下拉箭头提示遥控器选择菜单；菜单与连接页左侧设备卡片底部的型号选择入口一致，当前型号带勾选且不可重复选择；菜单各型号右侧增加对齐的连接圆点，绿色表示已连接、灰色表示未连接，当前选中项仍保留圆点颜色。连接状态基于当前 HID 设备快照，未选中的型号也按实际连接显示；共享硬件标识的小米型号按设备型号或唯一候选的 BLE 确认结果区分，不能确认时不标为已连接。切换后保存选择并加载该型号的配置。使用统计页保留时间范围与本机数据提示。

连接信息中的按键连接与语音连接统一显示“已连接／等待连接”。语音连接的扫描、协商、型号不符等详细原因通过悬停提示查看，不直接展开为长段状态文字。

连接页左侧设备卡片底部使用整行菜单按钮，直接显示当前遥控器名称，切换型号后同步更新：高度 36、圆角 8，文字左对齐，右侧使用灰色下拉箭头；以浅边框和背景区分可点击区域，悬停时加深边框与底色，并提示“更换遥控器”。整行均可点击，并保留原生菜单、键盘及辅助功能操作；辅助功能标签包含当前遥控器名称。

按键页按窗口可用高度自适应排布，按键卡片、操作区文字和遥控器图片同步放大，利用底部空间；图片保持原比例，连接线随布局对齐，最小窗口仍可完整展示所有按键，无需滚动。

Chromecast 遥控器（G9N9N）的图片去除机身底部的地面投影，保留机身本身的明暗和按键细节；按键页与连接页使用同一素材。

连接线主要在机身外侧转向，末端以短线和小箭头明确指入对应按键，避开按键符号；银色机身上的线使用深灰色，黑色按键上的线使用浅灰色。小米型号的右侧按键按实体目标从上到下排列（确认 OK、右、下、音量＋、音量－、自定义键），避免连线交叉。悬停卡片或遥控器图上的按键时，卡片、对应箭头连线及实体按键轮廓同步高亮；点击图上的按键直接打开该键的单击动作编辑，语音键打开语音配置。图上空白机身不触发编辑，支持通过键盘或辅助功能激活按键。打开编辑弹窗或离开页面时清除悬停预览。


G9N9N 同样按实体目标高度排列：方向「下」从左侧连入，电源键置于左列底部，输入源置于右列底部；右列的侧面音量键位于方向「右」与语音键之间。确认 OK 的箭头与方向「右」错开，输入源连线从右侧进入，不穿过电源键。

G9N9N 导航环的高亮与点击区域按照片分别校准内外椭圆：外沿中心略偏确认键右侧，方向区域贴合实体圆盘，不延伸到左侧机身；内沿与确认键之间保留间隙。

实际按压优先于悬停和当前选中项：同时按住多个实体键时，对应卡片、连线与轮廓全部高亮；松开后恢复悬停或选中项。按压与悬停使用相同的真实按键轮廓，以更亮的描边与填色区分按下状态；方向键仅突出导航圆盘中相应的四分之一区域，不添加通用圆形遮罩或常驻定位圆环。

按键卡片中的单击、双击、长按操作格使用中性灰底色和手势标签文字，与外层浅灰卡片形成层级；已配置动作的底色更明显，未设置项使用较淡底色和次要文字色，仍可点击配置。深色外观单独适配操作格亮度与文字对比度。操作文字不小于 11 pt；运行 Harness 列表、区域截图和切换原生模式在卡片中使用短标签，悬停及辅助功能仍提供完整动作名称。

未重命名的内置组合动作在按键卡片中省略应用名前缀，例如“Codex-转到最近聊天1”显示为“转到最近聊天1”，优先展示具体动作和编号。自定义动作与已重命名的预置动作保留用户命名；保存的全名、编辑器、悬停提示和辅助功能名称均不受影响。

按键页“恢复当前方案”与菜单栏“恢复当前方案的默认映射…”共用确认框，主窗口可见时在主窗口正中央弹出，主窗口未显示时沿用系统默认位置；默认按钮为取消。确认框显示方案名称、已绑定的 Harness 和覆盖范围；确认后仅恢复当前方案映射，全局按键和语音快捷键保持不变。如确认期间遥控器或方案发生切换，则取消恢复。

键位方案页的说明在“修改后对所有绑定的 Harness 生效。”之后固定换行，第二行展示方案不可删除的限制。

侧栏顶部居中显示 64 pt 应用 Logo，下方间隔 6 pt 展示应用名称；Logo 使用与设置页一致的应用图标。版本集中在设置页展示，不显示“本地构建”标签。设置页介绍卡片左侧使用 72 pt 图标与名称、简介并排的布局，并随窗口宽度伸展，项目链接放在简介下方；右侧版本区域固定为 340 pt，与左侧顶部对齐，通过分隔线区分，集中展示版本号、系统要求和更新操作。“版本历史”打开 GitHub Releases 页面（https://github.com/tokenzz-vip/RcHarness/releases）。应用语言直接显示“简体中文”，不显示尚未实现的语言选项。

设置页版本区的“检查更新…”使用 Sparkle 原生窗口检查、下载、验证并重启安装 GitHub Releases 的最新正式版；检查或更新期间禁用重复检查。新版本以应用展示版本号比较，按数字分段判断（如 0.4.10 高于 0.4.9）；本地版本与线上版本相同或更高时，统一显示已是最新版本，不因线上内部构建号较高而提示升级或降级。只有线上展示版本更高时才作为更新候选，系统兼容性、签名与安装校验仍由 Sparkle 处理。可开启“自动检查更新”（默认关闭），安装仍需用户确认；上次检查时间在“自动检查更新”右侧同一行显示，尚未检查时原位显示“尚未检查更新”。更新包与更新源均需通过 Ed25519 签名验证。更新服务未配置、启动失败或检查失败时，不在版本区显示原因，也不追加主面板错误浮层；失败原因写入统一日志。版本区保持显示上次检查时间或“尚未检查更新”，并保留版本历史下载入口；其他功能的操作通知不受影响。截图模式和单元测试不启动更新器。

应用升级重启后，若本机已安装的虚拟麦克风组件版本低于随包版本，自动发起组件同步更新，仍需 macOS 管理员授权；未安装时不自动安装，同版本跳过，较新版本不降级。安装前释放语音会话与音频输出，操作期间禁用重复安装和卸载，成功后刷新组件状态；取消或失败时保留警告或错误及连接页重试入口。组件更新会短暂重启系统音频服务，下次启动会再次检查版本。

设置页“诊断与支持”卡片只展示排查说明、“复制诊断信息”和“刷新状态”，不单独显示“统计仅存本机”提示及其分隔线。

Harness 入口采用“应用网格＋AI 星光”的线性图标，表示主流 AI Agent 应用合集；侧栏与页面标题使用同一图形。

侧栏导航依次为「按键」「Harness」「键位方案」「组合动作」「连接」「设置」，统计入口固定在底部。「常用语」作为「按键」下的子页面，从按键映射页底部工具栏「恢复当前方案」左侧的「常用语」纯文字按钮进入；打开常用语时侧栏保持「按键」选中，页面底部可返回按键映射。侧栏沿用同级 JoyHarness 项目的图标与排版：Harness 使用同一份 24 pt 网格与星光矢量路径，其余入口使用相同的 SF Symbols（22 pt、regular 字重），统计入口使用实心柱形图。图标区域统一为 28 × 28 pt，导航项高 72 pt，图标与 12 pt medium 标签间距为 8 pt；未选中项使用 76% 主色，选中项使用强调色。页面内的小尺寸 Harness 图标按同一路径等比缩放。

点击按键卡片中的单击、双击或长按会打开模态设置窗口，语音键也在弹窗中配置。修改即时保存，点击“完成”或按 Esc 关闭，关闭不会回退已保存的修改；弹窗打开时固定当前按键及映射方案。「设置」页仅指定一个实体按键作为全局按键；所有具体动作统一在「按键」页配置。所选全局按键与实体语音键卡片的右上角统一显示蓝色“全局按键”胶囊标记，表明设置对当前遥控器的所有方案生效。点击全局按键的单击、双击、长按或语音键卡片，直接打开对应编辑弹窗；弹窗注明对当前遥控器的所有键位方案和 Harness 生效。

首页设备卡片和连接页的遥控器型号选择菜单从控件底边向下展开，避免遮住当前型号和连接状态。

当前提供简体中文界面。设置页仅保留一个全局按键选择器，按遥控器分别保存实体键、动作和语音快捷键，在同一遥控器的方案间共享，默认使用电源键，可更换为语音键以外的任意实体按键；单击默认「打开运行 Harness 列表」、双击默认「系统区域截图」、长按默认「切换到原生模式」。新默认动作仅用于首次初始化，已有全局按键配置（包括未设置的手势）保持不变。全局按键的单击、双击、长按动作在「按键」页点击对应卡片配置。更换全局按键时保留其动作，原实体按键恢复使用各方案中的配置；方案中的映射保留，切换、复制、删除或恢复方案默认设置均不会改变全局设置。未配置双击、长按时，按下立即执行单击映射，释放时结束。

实体语音键固定绑定语音触发，不能换绑到其他实体按键，也不能设置普通动作、双击、长按或禁用。在「按键」页点击语音键卡片，分别选择「长按模式」与「点按模式」的快捷键。长按仅提供 Fn／地球键、左右 Command、左右 Option、左右 Control 七个单键；点按提供相同七个单键及任意两个不同键的 21 种组合，包含同类修饰键的左右组合。两种模式均默认 Fn／地球键。长按模式按住说话、松手后等待尾音排空再释放快捷键；点按模式按一次开始，之后仅遥控器任意按键可结束，结束用的按键及其释放被消费，不执行原映射。小米蓝牙遥控器 2、2 Pro 的点按模式保持禁用，但可以编辑并保存其快捷键。Google G9N9N 可手动选择点按模式，默认仍为长按；点按时同一语音键再次点击可结束，也保留任意普通遥控器按键结束的方式。全局按键与语音触发设置分别保存，对默认方案、所有自定义方案和 Harness 生效，优先于方案内相应按键的映射。升级或导入旧配置时忽略原先可变的语音实体按键选择，保留有效的语音触发修饰键，原 Fn 点按开关统一关闭并保存；旧全局按键若占用了语音键，则移回电源键并保留其动作。无效或禁用的旧语音动作恢复为默认 Fn，原方案中的普通映射保留。

首次升级沿用升级前当前方案的电源单击、语音触发设置，原 Fn 点按开关统一关闭；原来停用的电源双击、长按保持未设置，避免自动启用历史动作。导入旧版备份时从其默认方案提取电源单击和语音设置，旧备份中的 Fn 点按设置忽略并保存为关闭。映射模式下电源事件独立于主页键处理，并通过现有原生键值抑制链路避免同时触发系统动作，原生模式或退出应用时恢复。实机需确认该型号电源键上报的 HID 事件及原生动作抑制效果。普通按键设置双击后，单击等待约 0.3 秒；设置长按后，约 0.55 秒触发。语音键保持独立的按下/释放生命周期；如果 BLE 的音频开始通知晚于 HID 释放，应用会短暂保留释放动作，等待语音会话开始或超时，避免语音应用过早结束触发。

按键动作「切换到原生模式」只负责从映射进入原生模式；原生模式下不执行任何映射手势，也不保留遥控器返回入口。需要恢复映射时，在主面板开启「启用遥控器映射」，或点击菜单栏右键菜单中的「模式：原生」。动作编辑器会提示返回方式；旧配置及备份中的模式切换动作自动沿用这一单向行为，已有按键绑定保留。同时配置双击和长按时，第二次按住达到长按阈值会触发长按，抬起后不再触发双击。鼠标动作支持点击、滚动和四个方向的指针移动，点击与移动统一使用 Quartz 坐标。

「系统与媒体」分类提供「查看所有窗口 (Control + ↑)」，可用于普通按键、全局按键的单击、双击或长按，也可作为组合动作步骤。触发时发送一次完整的 `Control + ↑` 快捷键，松开遥控器按键不会再次触发，也不会持续按住 Control；实际效果遵循 macOS 当前的系统快捷键设置。

「系统与媒体」分类提供「显示桌面」，可绑定普通按键、全局按键或组合动作。应用启动时探测 Dock 是否提供 `CoreDockSendNotification`；支持时发送 `com.apple.showdesktop.awake`，在显示桌面和恢复窗口之间切换。探测不到该入口时，该动作不会出现在动作列表中。

「系统与媒体」分类提供「切换应用 (⌘ Tab)」，可绑定普通按键或全局按键的单击、双击、长按。首次触发按住 Command 并发送一次 Tab，打开 macOS 原生应用切换器；弹出后，触发它的同一实体按键临时作为 Tab，每按一次立即切换一项，不再识别该键原有的单击、双击或长按动作。按住 0.35 秒后每 0.12 秒继续切换；松开停止连续切换，停止操作 2 秒后自动释放 Command 并进入选中的应用。左右键可向前或向后选择，确认 OK 可立即进入，返回、主页或菜单取消；触发键本身同时是这些键时，优先作为 Tab。弹出期间其他遥控器按键不执行原映射，语音不会开始；触发、确认和取消按键的松开不会透传。断开、重新扫描或更换遥控器、切换模式、打开主面板、休眠或退出时取消并释放 Command。此交互动作不用于组合动作步骤，也不修改已有按键绑定。

普通按键的「系统与媒体」分类提供「打开运行 Harness 列表」，可绑定单击、双击或长按。触发后，在当前屏幕中央显示类似 macOS Command+Tab 的半透明图标浮层，仅列出 Harness 中已启用且正在运行的应用（包含手动添加及未绑定方案的应用）；不启动未运行的应用。顺序沿用 Harness 列表，默认选中当前前台 Harness，否则选中第一项。触发列表的同一实体按键临时用于切换候选 Harness，每按一次立即向后切换，按住 0.35 秒后每 0.12 秒继续切换；松开停止连续切换，停止操作 2 秒后自动激活所选应用。左右键立即循环选择，中间「确认 OK」激活所选应用并关闭浮层；返回、主页、菜单或键盘 Esc 关闭，键盘左右及回车、点击图标也可操作。图标较多时横向滚动并跟随选中项；空列表显示提示，可随时返回。

浮层期间所有遥控器输入由列表接管，左右和确认不执行原方案中的单击、双击或长按动作。打开时释放原先按住的合成按键并取消待触发手势、组合动作和语音；开启浮层的那次按下与确认后的松开不会透传到应用。应用退出或 Harness 停用、移除会更新列表，确认时再次检查运行状态；焦点切换、打开主面板、原生模式、断开遥控器或休眠时关闭浮层。确认切换应用后，按现有前台匹配规则加载方案；不修改已有按键绑定。组合动作不支持打开交互列表。

运行列表的毛玻璃背景、内容裁切与窗口阴影使用一致的圆角轮廓，四角保持透明，调整浮层宽度后同步更新阴影。

运行列表切换应用时先使用原生激活请求；后台状态下被系统拒绝时，使用已有辅助功能权限将同一个运行中的进程置于前台。两条路径前均重新校验进程与 Harness 启用状态。激活成功后，向同一运行进程发送与点击 Dock 图标相同的“重新打开应用”事件，让目标应用自行恢复通过 × 关闭的窗口；发送前再次校验，发送失败时提示切换失败。不通过应用 URL 重新启动程序；目标退出或停用时提示重新打开列表，缺少辅助功能权限时明确提示。该处理覆盖所有 Harness，避免首次切换成功、之后来回切换报错。

按键页以整套按键方案为编辑对象，可选择已有方案，或将当前设置另存为新方案。新建方案后自动选中新方案并跳转到按键映射页，直接配置按键。普通按键的单击、双击、长按修改保存到当前方案；当前选定的全局按键及语音触发设置始终保存到全局配置。底部的「设置全局按键」按钮跳转至「设置」页，指定一个全局按键。

基础动作提供「快速删除（按住连续退格）」，可绑定到普通按键或全局按键，默认绑定保持不变。仅配置单击时，按下立即退格一次，按住 0.35 秒后每 0.06 秒退格一次；配置了双击且长按未设置时，按住 0.55 秒后开始连续退格，双击仍执行其配置动作。也可将快速删除绑定到长按，按住 0.55 秒后开始连续退格，保留单击和双击动作；显式配置的长按动作优先于单击快速删除。松开、取消手势、断开遥控器、切换模式或打开交互浮层时停止连续删除。每次退格均发送完整的按下和释放事件，不依赖系统键盘重复；双击及组合动作中的快速删除只执行一次退格。原有 Backspace 行为不变，配置保存及备份保留新增动作。

“启用遥控器映射”总开关显示在统计页以外的页面顶部栏左侧，紧跟页面标题并垂直居中，说明文案通过悬停提示展示。开关对整个遥控器生效；关闭后，遥控器按原生方式工作，重新开启可恢复映射。页面内的滑动开关统一使用蓝色表示开启；窗口失焦时，已开启且可操作的开关改为低饱和度的灰蓝色，关闭状态保持中性灰色，禁用状态降低不透明度，避免将失焦误认为禁用。开关获得焦点时不额外绘制外框或外圈，仍支持空格键切换。

组合动作页采用固定高度的双栏布局：左侧列表随窗口宽度适配，通常占两栏可用宽度的约 32%，宽度控制在 260–360 pt，右侧优先保留至少 520 pt 的编辑空间；左侧动作列表使用紧凑行距，名称与步骤数量上下排列，滚动条靠近面板右边缘；左侧动作列表和右侧步骤编辑区分别独立滚动，滚动较长的动作列表不会把右侧编辑内容卷走。左侧标题和“新建”入口、右侧名称编辑和底部“绑定到遥控器”“删除组合动作”操作保持可见。“添加步骤”紧跟最后一个步骤下方并靠左对齐，随步骤内容滚动；没有步骤时紧跟空状态提示。进入页面默认选中首个动作；切换动作后步骤从顶部显示。列表为空时显示“创建第一个组合动作”；创建后自动选中新动作、滚动到列表中的对应项，并在右侧打开编辑。添加步骤后自动滚动到内容末尾，让新步骤及其下方的“添加步骤”按钮可见，便于连续添加；删除当前动作后选中剩余列表的首项。

组合动作支持「通用」及全部内置 Harness 名称（Codex、Claude、Cursor、DeepSeek、WorkBuddy、OpenCode）标签。右侧编辑区可多选或清空标签，修改后自动保存；标签仅作为筛选信息，与 Harness 的启用、安装、前台匹配、方案绑定及动作执行无关。左侧筛选框下方展开与控件等宽的紧凑多选列表，每行 28 pt，整行可点击，选中项以小勾标记；连续选择保持展开，点击外部或按 Escape 关闭。默认显示「全部标签」，选中标签各自显示为浅底细边框的小圆角标签，按选择框实际宽度尽量显示完整名称，仅在放不下时用同样样式的「+N」表示未显示的标签数量；宽度变化时自动调整，按键编辑器中的筛选框使用同一规则。勾选一个或多个标签时显示至少命中其中一个标签的动作，「通用」也只匹配明确勾选「通用」的动作。切换筛选时优先保留仍可见的选中动作，否则选中筛选结果首项；筛选为空时提供显示全部动作入口。编辑标签使动作移出当前筛选时保留右侧编辑器，便于继续修改。新动作默认使用「通用」，在标签筛选下新建时使用当前标签集合。标签随配置导出、导入、恢复及删除撤销保留。读取没有标签字段的旧配置时，按固定 ID 给内置预置动作补上对应应用标签（保留重命名及步骤），其他动作归入「通用」；之后不再根据动作名称或 Harness 状态自动改变标签，也不重新补回用户已清空的标签。

按键编辑弹窗中的触发方式、动作分类、执行动作及引用选择使用统一的标签列宽和列间距，控件左边缘对齐。执行动作列表按「禁用 → 自定义动作（录制的快捷键、打开应用、输入常用语、执行组合动作）→ 基本按键 → 系统与媒体」排序；按分类筛选时仍将「禁用」置顶，并保留当前已选动作。按键编辑弹窗（含全局按键）选择「执行组合动作」后，在组合动作下拉框上方显示同一组「筛选标签」，默认「全部标签」，可多选「通用」及内置 Harness 标签，候选动作至少命中其中一个标签。执行动作、常用语、标签筛选及组合动作选择均从选择框正下方展开与控件等宽的原生弹层，位置不随已选项在列表中的序号变化；下方可用空间较少时缩短列表并在弹层内滚动。各选择器沿用组合动作页的行距、小勾和悬停样式；标签可连续勾选，其他选择保持单选，选定后关闭弹层。重复选择当前动作只关闭弹层，保留已配置的应用路径、快捷键和引用。较长动作列表在弹层内滚动，打开时定位当前已选动作。组合动作步骤中的嵌套动作选择器也提供相同筛选。筛选仅作用于当前选择器，不修改标签、按键绑定或动作步骤，也不跟随当前 Harness 自动切换；已选动作不属于当前标签时，仍单独保留「当前已选」项并提示现有绑定不变。空筛选提示切换标签；失效引用继续显示删除提示，嵌套动作继续禁止循环引用。

首次启动、升级或导入尚未初始化默认组合动作的旧备份时，自动补入 26 个 Codex、39 个 Claude Code 桌面版、35 个 Cursor、27 个 DeepSeek Harness 桌面版、24 个 WorkBuddy 和 59 个 OpenCode 桌面版快捷键动作。动作名称分别统一以 `Codex-`、`Claude-`、`Cursor-`、`DeepSeek-`、`WorkBuddy-` 和 `OpenCode-` 开头。已有相同 ID 或同名（忽略首尾空白和英文大小写）的动作保留原样，不重复添加或改动按键绑定。默认动作可编辑、重命名和删除；初始化状态随配置保存和导出，重启及导入新版备份均不会恢复已删除的动作。升级只补入新版本增加的动作组，不恢复此前已删除的 Codex、Claude 等旧动作。

Codex 动作按 [官方 macOS 默认快捷键](https://learn.chatgpt.com/docs/reference/commands) 配置。Claude 动作按 [Claude Code 桌面版快捷键](https://code.claude.com/docs/en/desktop#keyboard-shortcuts) 配置，覆盖新建/关闭会话、环境选择、会话切换、停止回复、接受建议、差异/浏览器/终端面板、分屏、侧边聊天、视图模式和权限/模型/努力程度菜单，并展开环境与菜单中的数字选项。Cursor 动作按 [官方快捷键文档](https://cursor.com/docs/reference/keyboard-shortcuts) 配置，覆盖侧边面板、Agent 布局/模式、模型切换、语音输入、会话/标签页、消息发送与队列、上下文、接受/拒绝更改和补全；相同快捷键在不同焦点或上下文中的用途分别列出。

DeepSeek 按 [官方 Harness 客户端](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/client) 在 macOS 桌面版中的默认绑定配置，并与本机应用包中的注册表核对，覆盖会话新建/搜索/重命名/分叉/归档、工作区、左右侧栏、分屏、页面、文件、浏览器、终端、设置、消息输入、审批和字号。Enter 按应用的忙时设置发送；⌘Enter 使用另一种忙时发送方式。停止回复动作连续发送两次 Esc，间隔 0.1 秒，适用于会话或输入框焦点且未被菜单、审批或弹窗接管时；应用默认双击判定为 0.5 秒，若用户缩短过该判定，需相应修改步骤间隔。

WorkBuddy 按本机 macOS 应用内置的快捷键目录配置（可在[系统设置的「快捷键」页](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)查看），覆盖对话/快速问答、搜索、任务切换与定位、消息、面板、全屏、字号、选择器、斜杠命令、标签页及语音录制开关。不预置全局唤起/隐藏窗口和纯修饰键手势。除 DeepSeek 双 Esc 外，每个动作只发送一次快捷键；所有预设均在对应应用前台及相应上下文中使用，不自动启动或切换应用。应用版本或自定义快捷键与预设不同、使用非美式键盘布局导致 `@` 等字符位置不同时，需相应修改步骤。

OpenCode 按本机 2.2.7 macOS 桌面版内置注册表配置，并与[官方桌面菜单](https://github.com/anomalyco/opencode/blob/dev/packages/app/src/shell/commands/desktop-menu.ts)及[会话命令](https://github.com/anomalyco/opencode/blob/dev/packages/app/src/session/commands/use-session-commands.tsx)核对，覆盖会话/窗口/标签页、未读会话、主页与查找、项目与工作区、文件与上下文、侧边栏/审查/底部/终端面板、模型与变体、Agent、MCP、自动批准、后台任务、消息输入和字号；会话标签页 1–9 展开为独立动作。⌘W 优先关闭侧面板标签页，⌥⌘W 关闭会话标签页；⌘T 在侧面板焦点中打开侧面板标签页，标签页导航也随焦点生效。⌘数字在侧面板焦点中选择对应侧面板标签页（⌘9 选最后一个），否则选择可见的会话标签页。Enter 按忙时设置发送，⌘Enter 使用另一种忙时发送方式；停止回复的 Esc／⌃G 需要输入框焦点。切换工作区仅在新建会话页且工作区功能可用时生效，Agent 和底部面板动作也取决于相应功能是否可用。升级到此预设版本只补入 OpenCode 动作，不恢复已删除的旧应用预设；后续编辑、重命名或删除同样随配置与备份保留。

组合动作列表中每个条目的整行卡片均可点击，点击名称、步骤信息、右侧空白区域或箭头都会选中并打开对应编辑器。

组合动作名称必须唯一且不能为空，比较时忽略首尾空白和英文大小写。新建时自动生成不重名的名称；修改名称后点击“保存名称”或按回车确认，重名时会提示并保留原名称。已有配置和导入文件中的空名称或重名项会自动补名或添加序号，保留动作步骤和按键绑定。

组合动作的步骤支持“执行组合动作”，可以多层嵌套或重复调用同一子动作。子动作按顺序执行完毕（含其末尾等待）后，再等待父步骤设置的时间并继续下一步。编辑器禁止直接或间接的循环引用；执行前会检查全部引用，遇到循环、引用缺失或展开后超过 100 个步骤（含嵌套调用步骤）时提示错误且不执行。每次执行使用当前配置的快照；切换原生模式、遥控器断开或触发新的组合动作会取消剩余步骤。

执行快照包含常用语文本；执行途中编辑或删除常用语不影响本次输出。组合动作不支持模式切换；旧配置若含此步骤，会在执行前提示并拒绝整次执行，不再静默跳过。

除使用统计外，各页面右上角均显示遥控器连接状态与电量卡片。Harness 页面内显示原生应用图标、运行状态和方案选择器，不提供「添加应用」入口；已保存或导入的自定义应用仍可管理。点击已绑定的 Harness 即切换到它对应的按键映射；前台应用切换到已启用的 Harness 时也会自动加载对应方案。每个 Harness 可为不同遥控器分别绑定一个按键方案，同一遥控器的方案可绑定多个 Harness，数量不受限制；修改共享方案会对所有绑定的 Harness 生效。默认方案、Codex／Claude／Cursor／DeepSeek／WorkBuddy／OpenCode 的同名方案（含「应用名 按键方案」，忽略首尾空白和英文大小写）以及仍绑定任意 Harness 的方案不可删除，不显示删除入口；内置同名方案即使未绑定也受保护。绑定保护也适用于已停用的 Harness 和自定义应用，底层删除操作同样受保护。更换或解除某个 Harness 的绑定不影响其他 Harness；停用保留绑定；移除 Harness 保留方案；其余方案解除全部绑定后才可删除。未匹配或未绑定时使用默认方案。

小米蓝牙遥控器 2 与 2 Pro 共用 HID VID/PID 和通用蓝牙名称，必须读取 BLE Device Information 的型号后才能确认按键连接：RC001／RC001-MS 只匹配普通 2，RC003／RC003-MS 只匹配 2 Pro。确认前、型号不符或 BLE 断连后，按键显示等待连接并暂停该配置的映射；映射模式仍持续抑制当前选中型号所匹配设备的原生按键，避免系统语音快捷键抢先唤起输入框，未选中的小米只抑制语音键（F5 及语音 usage 别名），保留其他原生按键，避免触发系统听写或提示音；即使当前选择 Chromecast，此保护仍生效。选择错误型号时，语音连接显示等待连接，悬停可查看实际读到的型号与当前选择不符的详情；不会因发现相同 VID/PID 而将两款配置都显示为已连接。语音就绪仍须完成能力协商。小米 2 与 2 Pro 可以同时保持连接；BLE 逐只读取候选型号，HID 监听和原生按键抑制同时核对各物理设备在 IORegistry 中的 ModelNumber，完整按键映射只处理当前选择的型号。设备型号缺失时，仅在同 VID/PID 下只有一个物理候选时允许沿用 BLE 型号；多个候选时不作归属推断。

键位方案归属于遥控器型号。「按键映射」顶部方案下拉框、「键位方案」列表和 Harness 方案选择器只显示当前遥控器的方案；新建、复制、重命名、删除和恢复默认也只作用于当前遥控器。不同遥控器可以使用相同方案名；默认方案、当前选择、Harness 绑定和全局按键分别保存，切换回来或重启时恢复各自配置。Harness 应用信息、启用状态、组合动作和常用语仍然共用。

每款遥控器首次使用、升级或导入旧配置时，补齐尚未初始化的 6 个内置 Harness 默认按键方案：Codex、Claude、Cursor、DeepSeek、WorkBuddy 和 OpenCode。Codex 使用上述专用映射，其余 5 个使用通用默认映射；各方案独立保存，当前型号不支持的按键不显示。已有有效绑定、方案映射、应用启用状态和当前选择保持不变；缺少内置应用时补入，已有相同应用时不重复添加。同名未绑定方案保留，新建方案自动添加序号。初始化标记按遥控器保存并随备份导出，之后主动修改、换绑或解绑均不会因切换遥控器、重启或导入新版备份被覆盖。

「设置 → 通用」将「配置导入与导出」置于分组最上方，「显示键位方案前缀」紧随其后。

「设置 → 通用」在「应用语言」下方提供「主题模式」：跟随系统、浅色、深色，默认跟随系统。切换后立即应用到整个应用的窗口和弹窗，并记住本机选择，重启后恢复。选择「跟随系统」后，应用随 macOS 外观变化。

所有按键方案都保留所属遥控器的固定前缀：小米蓝牙遥控器 2 为 `RC1-`，2 Pro 为 `RC3-`，Chromecast 遥控器为 `G9N-`。「设置 → 通用 → 显示键位方案前缀」默认关闭，并记住本机选择；仅控制方案列表、选择器、按键编辑说明、创建/复制提示和新建/重命名弹窗中的前缀显示。开启时，新建和重命名弹窗在输入框前展示不可编辑、不可删除的前缀，只允许修改后面的方案名称。关闭不会删除真实前缀，也不会改变方案名称、映射或 Harness 绑定；再次开启或切换遥控器时仍显示相应型号的前缀。复制、保存及导入/导出沿用原有结构：型号保留固定前缀，方案只记录可编辑名称，不重复添加前缀。

旧版 Harness 内的按键映射会自动迁移成独立方案并建立绑定，原有方案也会保留。升级时，原先共用的键位方案和绑定归入升级时选中的遥控器；其他遥控器首次使用时创建独立默认方案及内置应用方案。配置导出使用版本 4，包含所有已配置遥控器的方案、全局按键和绑定关系；导入兼容版本 1、2、3，旧备份归入当前遥控器。导入版本 4 时按型号恢复，若当前遥控器未包含在备份中则创建它的独立初始方案，不套用其他型号配置。

内置应用包括 Codex、Claude、Cursor、DeepSeek、腾讯 WorkBuddy 和 OpenCode；OpenCode 使用 `ai.opencode.desktop`，升级和导入旧配置时补入并为各遥控器创建独立的「OpenCode 按键方案」，沿用通用默认映射及初始化保护；DeepSeek 对应 DeepSeek Harness（Bundle ID 为 `com.deepseek.dsh`）。WorkBuddy 使用 `com.tencent.workbuddy.mac`，兼容旧版 `com.workbuddy.workbuddy`；升级或导入旧配置时自动补入 WorkBuddy，已存在相同应用时不重复添加，保留已有条目的方案绑定、名称和启用状态。首次初始化未绑定的内置 WorkBuddy 时，自动创建并绑定独立的「WorkBuddy 按键方案」，采用通用默认映射：方向键、Enter、Backspace、Esc、切换到原生模式、音量和截图；全局按键与固定语音触发继续由全局设置覆盖。同名方案已存在时为新方案添加序号；已有有效绑定不变。初始化状态随配置保存和导出，之后修改、换绑或解绑，重启及导入该备份均不会重新创建或强制绑定；「WorkBuddy 按键方案」在解绑后仍不可删除。

旧配置及导入备份中的内置 Antigravity 会自动替换为 DeepSeek，保留方案绑定、启用状态和已初始化标记，并清除旧应用路径。主动解绑的方案不会重新绑定；版本 4 中各遥控器的旧应用绑定、初始化标记和已选应用一起迁移，已有 DeepSeek 的明确绑定或解绑优先保留。其绑定的「Antigravity 按键方案」同步改名为「DeepSeek 按键方案」，已替换应用的配置也会补迁移；重名时自动添加序号，用户自定义方案名保持原样。

停用 Harness 后仍可编辑其绑定方案，编辑不会启用该 Harness。旧备份缺少 Harness 数据时，补入的内置应用不会抢占旧方案的应用关联。

Harness 页面各行的高度和控件位置保持稳定，窗口获得或失去焦点、前台应用变化时，“当前”标记的显隐不会推动其他行或改变页面高度。

菜单栏使用“遥控器 + AI 对话窗口”的单色图标，自动适配浅色与深色外观。悬停可查看连接、语音就绪与映射模式状态；左键打开主面板，右键打开操作菜单。启用“启动时打开主面板”后，冷启动会在应用激活后直接显示主面板。关闭主窗口后，RcHarness 继续驻留菜单栏并隐藏 Dock 图标；再次从菜单栏打开主面板时按设置恢复 Dock 显示。

统计仅保存次数、日期和时长，不记录音频或听写内容；主动编辑的常用语和配置仅保存到当前 Mac。硬件语音链路和第三方 App 兼容性仍需实机验收。

音频引擎及播放器的创建在专用队列完成，冷启动不阻塞语音键触发与 BLE 收包；取消尚在准备的播放图也不等待初始化返回。音频设备启动期间最多保留 5 秒的首句音频，准备完成后按原速顺序播放，追平后恢复平时半秒的待播上限；排空时限随待播音频长度增加，松手后等待尾音完成再释放触发键。准备超过 5 秒或启动积压超出 5 秒容量时明确报错并结束本段，避免只把最后半秒当作正常录音。此处理覆盖启动丢失首句的问题，不代表输入法识别结果已获确认。

语音排行每天保留的最长记录条数取所有已支持遥控器的最大按键数量（目前为 15 条），日、周和全部排行从这些记录计算。音频设备列表包含双向虚拟设备，以及明确识别的 `MiRemoteV2ch_UID` 回环设备；普通 USB 耳机、内置声卡和蓝牙耳机不会作为回环输出。第三方虚拟设备仍需具备实际回环能力。0 dB 不额外放大，降噪、增益、最终限幅在同一处理链完成；准备、传输、尾音排空和输出错误会分别显示。音频配置在独立串行队列执行，首包等待设备、引擎和播放器就绪；系统配置变化导致引擎停止时，每段语音最多自动重建两次播放图并重放未确认播完的音频，持续失败时结束会话并提示。取消会话会清空自带 HAL 的旧音频，不改变系统默认输入和输出。

收音支持音频早于 START 的到达顺序，迟到 START 会接续首包的解码状态；STOP 后 300 ms 内的无控制音频、取消后 1 秒内的旧 START/音频会被拦截，新语音键按下会重置保护。睡眠时停止语音并释放按键，唤醒后重新连接。测试音按实际播放完成反馈结果。融合说明和验证边界见 [音频融合记录](audio-integration-2026-10-28.md)。

音频诊断保存在 `~/Library/Logs/RcHarness/audio.log`，单文件约 512 KiB，另保留一份轮转日志；记录收包/字节/解码样本、首 PCM 延迟、半帧丢弃、准备耗时、播放与失败计数，不保存音频或听写内容。

主应用具有单实例保护，重复启动会唤起已有窗口。配置读取失败时，原始数据会保存在同一偏好设置域的 `RcHarness.recovery.*` 键中。逐按键及原始 HID 日志默认关闭，排查时可设置 `RC_HARNESS_REMOTE_TRACE=1`。

运行列表的诊断元数据使用统一日志的 `switcher` 分类，默认记录普通全局按键的按下/释放、映射模式与列表接管状态，以及含打开列表动作的手势最终识别为单击、双击还是长按。浮层记录显示后的可见性、键盘焦点、当前空间状态及关闭原因（例如应用切换、失焦、遥控器取消、断连或休眠），便于区分“没有触发打开”和“打开后立即关闭”；不记录组合动作内容或常用语文本。可用 `log show --last 10m --info --predicate 'subsystem == "vip.tokenzz.rcharness" AND category == "switcher"'` 查询。

语音快捷键通过按键面板选择，配置期间不监听实体键盘。普通按键及组合动作的快捷键仍可在当前窗口录制，失去焦点、窗口不活跃或移除录制控件时取消，并在所有按键释放后保存。录制不再创建全局 Event Tap、开启安全输入、监听原始键盘 HID 或临时屏蔽修饰键。升级启动时仅恢复旧版未完成录制留下的键盘映射日志，不再新增键盘屏蔽。

语音编辑弹窗显示长按、点按两张模式卡片，通过紧凑的快捷键选择面板选择。面板使用键帽样式展示当前选择，按键选项的符号也使用键帽展示，左右侧名称保持单行；长按提示点击其他按键即可更换，点按选满两个键时提示先取消一个再更换。点按支持七个单键和 21 个双键组合；组合按固定顺序按下两个实体键，再反向释放，携带各自左右侧标志，结束后不残留修饰键。面板会根据屏幕剩余空间向上或向下展开，空间不足时只滚动按键区，底部的取消和确认始终可见。两种模式默认 Fn；升级、导入和重启保留符合新范围的选择，旧 Fn+Space、普通字母快捷键、含 Shift 的绑定或其他不受支持的值回退为 Fn。缺少点按设置的旧备份也补入 Fn。小米蓝牙遥控器 2、2 Pro 只能选择长按模式，点按卡片注明「此遥控器不可用」，但快捷键仍可编辑。Google G9N9N 可选择点按模式，并提示与输入法的点按快捷键保持一致、首次确认松手后仍能收音；不兼容时可切回长按。历史 Fn 点按兼容开关关闭，不作为新的点按模式；导入含点按启用状态的备份，小米两款仍强制使用长按，Google 保留点按选择。两种快捷键和模式随全局设置保存、导出。HID/BLE 乱序和连续按键按独立会话处理；长按模式的短按不会让遥控器在松手后持续采音。Google 点按沿用原生 HTT 按下／释放通知（16 kHz 编码，声明模型级别 3），采用 ATVVoice 点按时序：按下时保留原生流并发一次输入法开始快捷键，同次 START_SEARCH 不重复触发；首次按下不足 550 毫秒时，在真正收到松手 STOP 后发送 MIC_OPEN（实时音频模式 0），保留输入法会话和已缓存尾音。再次原生按下会标记为结束动作，松手后结束且不再开麦；按住达到 550 毫秒则松手结束，不锁存。没有对应原生按下的多余松手通知不会结束主机开启的流。没有原生 START 的 START_SEARCH 仍可发起主机请求；独立 HID 点击在释放后合并同次 BLE 通知。MIC_OPEN 发出后须在 1 秒内收到可解码的音频帧，只有 START 回复、重复 STOP 或不完整音频都不会延长该期限。未收到 STOP 的主动停止最多等 0.5 秒；持续收音每 5 秒续期，连续 2 秒无音频或单段流达到 120 秒会主动结束输入法会话。排空结束前的新开始点击不打开另一段收音；断连、休眠、权限／输出失败、切换模式或遥控器以及退出会取消全部点按状态和定时任务。迟到的主机 START 和音频不自行唤起输入法。Google 长按及小米原有协商参数与收音生命周期保持不变，小米点按仍禁用。2026-11-11 用户确认当前 G9N9N 固件 26.2 与输入法配置的测试效果暂时满足要求，日志已有松手后持续约 9.48 秒收音并由第二次点按正常结束的样本；仍有零音频超时尝试，其他固件及输入法需分别确认，详见 [G9N9N 适配说明](google-g9n9n.md)。诊断日志记录语音键及会话元数据，普通按键追踪仍默认关闭。已确认的唤起缺陷、修复和验收边界见 [语音触发审查](voice-trigger-review-2026-10-28.md)。

语音触发使用 Command、Option 或 Control 时，模拟事件同时携带通用修饰键标志和对应左右侧的设备标志，以兼容按左右键标志识别按下/释放的快捷键监听器。目标输入法的快捷键和麦克风需要分别与 RcHarness 的触发按键、回环输出对应；例如微信输入法应在「语音输入 → 麦克风」中明确选择 RcHarness 当前使用的回环设备。按键、BLE 收音和音频播放计数正常，不能单独证明目标输入法已开始听写。微信输入法的故障说明见 [2026-10-29 复查](voice-trigger-review-2026-10-29.md)。

同一遥控器不应同时交给 Joy Harness 等另一款映射程序处理，否则一次按键可能收到多个进程发送的修饰键。其他映射程序退出时也可能恢复设备级映射，令原始 F5 重新出现；此时需在 RcHarness 关闭再开启按键映射，重新建立抑制。

Fn 使用明确的 HID 事件来源状态，按下和释放共用同一事件来源；仅选择 HID 投递位置不会将默认的会话来源状态改成 HID 状态。该调整与真实 Fn 的来源状态对齐，第三方输入法是否接受仍需实机验证。Fn 和含 Fn 的组合快捷键按下、释放使用相同的 HID 事件来源；长按释放仍等待音频排空。

Codex + 微信输入法的一组已实测配置为：微信输入法「按住说话」和 RcHarness「按键 → 语音键卡片」的「语音触发按键」都设为地球键（Fn），Fn 点按不可用，微信输入法麦克风选择「RcHarness 遥控器麦克风」，同一遥控器仅由 RcHarness 映射。实测遥控器可唤起语音浮窗并输入识别文本；右侧 Command 也已独立验证可用。松手后的修饰键释放仍等待音频排空。

按键恢复辅助进程在后台直接运行，不初始化图形界面，也不单独显示 Dock 图标。设备从仅保护语音键扩展为完整按键保护时，新接管的按键以接管当时的映射作为恢复基线，先保存日志再修改系统映射；接管前其他工具的改键或删除映射会保留，中途写入失败仍可恢复。

同一输出键码由多个映射同时按住时，最后一个持有者松开才发送释放，并沿用首次按下的事件来源。不同修饰键的普通按键组合仍发送各自的按下；一次性快捷键（含截图）与已按住的普通键重叠时，也会执行本次按下，不提前释放原有按键，不残留本次快捷键的修饰键。共享修饰键仍只发送一组按下和最终释放。

前台应用反复匹配到当前方案且映射没有变化时，不重新保存配置或通知映射变化；实际切换方案时，将应用与方案选择作为同一份遥控器配置保存。方案切换不影响已按下输出的释放和正在进行的语音会话。

## 本轮优化后的行为（2026-10-29）

- 切换按键方案（包括前台应用变化触发的自动切换）不再取消正在进行的语音会话或按住的手势。会话和手势在按下时记录映射，松开时释放当时按下的输出。

- 启动、切换型号、蓝牙重新打开及连接失败重试时，先按语音服务查找系统当前已连接且名称匹配的候选；唯一候选立即连接，避免旧蓝牙 UUID 导致两轮连接超时。候选不唯一时，若记住的 UUID 仍在已连接候选中，则优先尝试该设备；同名小米在尝试失败后继续轮换其他候选并严格校验型号。没有合格的已连接候选时才尝试记住的 UUID，连续两次失败后转入扫描。扫描每 10 秒暂停并重新查找已连接设备，再尝试缓存，避免已连接但不广播的遥控器被遗漏；更换遥控器或重新配对后无需手动清除配置。


## 全型号审计修复后的行为（2026-11-06）

- BLE 连接按型号独立记住成功协商的 peripheral UUID；旧版共用 UUID 在首次成功连接时迁移，切换型号保留各自的新记忆。型号不符时主动断开候选并暂时排除 30 秒，继续寻找其他设备，不放宽身份校验。G9N9N 仍支持型号或有效 PnP 身份确认，两个响应的先后顺序不影响结果；小米保持严格型号校验。
- G9N9N 固件 26.2 已实测 14 个普通按键的按下／释放，以及语音键按住采音、松手停止、输出排空与快捷键释放；输入源的 Consumer usage 为 `0x89`，同时兼容旧映射 `0x189`。该固件的型号字符串 `A0` 仅用于诊断展示，语音身份通过精确 VID/PID 的 PnP 校验确认，接受真机使用的厂商来源 1 及原有来源 2；不单独信任 `A0`。本次语音协商为 ATVV v1／16 kHz／160 字节帧，电量读取成功。
- 连接与协商有 20 秒截止时间，失败后按 1、2、4、8、16 秒退避重试。没有候选时每 10 秒复查；同名小米候选不唯一时依次连接并严格读取型号，型号不符的候选暂时排除，超时或失败后轮换候选，成功协商后才记住该型号的 UUID。其他设备候选不唯一且无法通过已连接的记忆设备确定目标时，每 10 秒复查，候选减少为唯一后自动继续。停止、关闭蓝牙或更换候选会取消旧定时任务，旧设备回调不能清理另一设备的连接。
- HID 解析记录全部活跃输入，包括普通键、Hat Switch 和同一按键的不同 usage 别名；重复报告不会重复触发手势。移除一个 HID 服务时仅取消已无其他来源持有的按键，释放该键原有输出并取消尚未触发的单击、双击或长按，不把设备移除当成一次正常点击。其他设备仍按住的相同输入继续保持。
- 合成键盘、鼠标键和媒体键按活跃持有数合并：第一次按下发出 down，最后一次释放发出 up。普通动作与语音快捷键共享同一输出边界，释放一个动作保留其他动作仍持有的修饰键；同一键的一对事件沿用第一次按下的事件来源。
- 未选中小米的语音键保护同样从 scalar usage 表提取，不启动该设备的键位映射或语音会话；HID 发现同时观察这些设备的连接与移除，在当前选择 Chromecast 时也会刷新保护。
- HID 解析与原生按键抑制使用同一份 scalar usage 表，覆盖固件可能上报的别名；抑制只写入键盘和 Consumer HID 服务，跳过同一 VID/PID 下的鼠标指针服务。恢复原生键值时最多尝试 4 次，间隔从 0.5 秒倍增；恢复后的映射经读回确认，成功项从恢复日志移除，失败项保留供下次启动继续恢复。辅助进程持续失败会以失败状态退出，应用存活时提示保护进程异常。
- 已实测型号（RC001-MS、RC003-MS、G9N9N）的连接页与型号菜单不显示验收标签，连接页也不显示重复的实测通过说明；实测状态保留在诊断信息和适配文档中。小米连接页提示两款可同时连接、当前仅控制所选型号；多设备归属以各自型号为准。
- G9N9N 的语音键仅有 BLE 边沿时，语音流连续 2 秒没有音频包或单次达到 120 秒会主动发送关闭命令，补齐松手与结束事件，排空已收到的尾音后释放快捷键。正常 STOP、取消、断连和替换会话均撤销旧超时；超时后的迟到音频不能单独开启新会话，需新的语音按键或显式启动通知。小米沿用 HID 松手后的既有排空保护。
- 两款遥控器的语音命令写入失败时，清除就绪、型号及会话状态，通过连接控制器自动退避重连，不向失败的写入通道重复发送关闭命令。电量服务的特征发现失败只将电量降级为未知，不中断按键型号确认或语音连接；核心语音与身份服务失败仍触发重连。
- 连接信息面板的按键连接与语音连接始终只显示“已连接／等待连接”，不在面板底部追加状态说明；连接中、断开、蓝牙未授权、型号不符、协议失败、语音超时以及收音期间均保持相同布局。语音连接的详细原因通过悬停提示查看，诊断信息保留完整状态；传输语音、输出尾音等实时进度统一显示在「遥控器语音」面板底部已有的音频状态位置，悬停可查看完整收音与输出状态。
- 「刷新音频设备」主动使缓存失效并重新枚举，日常状态更新继续使用缓存。语音时长由可注入的单调时钟计算，系统日期仍用于按天归档，调整系统时间不会改变一段语音的持续时间。
- 「复制诊断」包含应用版本、当前型号与适配成熟度、实际/最近检测型号、BLE 阶段、ATVV 协商帧长、最近连接失败、输出 UID、权限及音频状态，不包含音频或识别文本。共享语音传输日志使用 Remote 标记，避免将 Google 设备误标为 Xiaomi。

左侧“按键分配”卡片的“返回按键映射”入口固定在卡片底部，与上方使用说明留出弹性间距。

中间列表以“常用语库”为标题，下方展示排序提示与条目数量。

五向推荐默认绑定为：上“继续执行”、下“检查结果”、左“解释一下”、右“修复问题”、确认“确认方案”。新安装或首次升级到推荐绑定版本且五个位置均未绑定时，一次性应用这些默认值；已有任意位置绑定时保留整组配置。后续修改、解除绑定或导入配置后，不会在重启时重新绑定；已删除的推荐条目不会因此恢复。单击输入对应中文正文，双击输入对应英文正文。

首次使用或升级到内置 AI 常用语的版本时，一次性补入 16 条中英文提示语，涵盖继续执行、确认方案、计划、需求澄清、解释、总结、方案对比、查漏、排错、修复、测试、验证、优化、审查、润色及交接。内容 1 为中文，内容 2 为对应英文；条目可以编辑、删除、排序和绑定。补入时保留原有条目的内容、ID、顺序及按键绑定，已有相同 ID 或相同双语正文的条目不重复添加，同名但内容不同的新条目自动添加名称序号。重启不会重复添加或恢复已删除的预置语；导入配置以备份中的常用语列表为准。

常用语设置分为三栏：左侧按键分配以遥控器方向环和中间确认键展示五个位置，点击位置选择一条常用语。轮盘由单一原生鼠标输入层按可见扇区和确认键的实际形状命中，图标、文字及扇区空白均可点击，不受透明按钮矩形重叠影响；扇区间隙不拦截点击，从一个扇区拖动到另一个扇区后松开不触发分配。选择弹窗优先在点击位置右侧展开，屏幕空间不足时由系统调整位置；箭头指向点击的方向或确认键，标题显示对应按键，轮盘以强调色轮廓标出正在编辑的位置；关闭弹窗后恢复。弹窗默认聚焦搜索框，支持对两组内容的标题和正文进行模糊搜索，忽略英文大小写、重音和全半角差异，支持按顺序输入不连续字符以及用空格组合多个关键词；结果保留常用语库原有顺序。每次打开清空搜索，始终保留“不分配”入口，搜索无结果时也能解除当前按键的绑定；选择后立即保存并关闭弹窗，不影响其他按键。说明与绑定数量、轮盘、单击/双击说明、唤出提示之间均保留弹性间距，随卡片高度均匀分配空间，返回入口位于底部；轮盘采用中性灰的四向分区和独立确认键，底色与按键映射中已配置的操作格保持一致，边框清晰区分卡片背景，悬停和按下时逐级加深，并适配深色外观；下方单击/双击说明放在带浅底和边框的独立说明区，使用强调色序号、半粗体手势标签和主文字色说明。已绑定项以名称旁的小勾标记，不使用常驻蓝色填充或圆圈，在键盘聚焦或打开该位置的分配弹窗时使用强调色轮廓。设置页和唤出的常用语浮层均采用五向圆盘，浮层隐藏重复的绑定小勾；中间“常用语库”列出标题，列表条数位于排序提示同一行的右侧，与“新建”按钮右边缘对齐；已绑定的条目在标题后显示对应方向键或确认键符号，同一条目绑定多个位置时显示全部符号；绑定、更换和解除后，列表在下一次界面刷新时同步更新置顶顺序、方向标记及拖拽手柄，无需再次点击或切换页面；支持新建和选择。已绑定条目按“上、下、左、右、确认”自动置顶，同一条目绑定多个位置时只出现一次，按最靠前位置排序。其余条目在标题前显示拖拽手柄，可从手柄或整行按住拖动，通过原生列表插入线调整顺序，排列自动保存并随备份导入导出；置顶条目的固定顺序优先于拖拽，解除绑定后恢复到手动顺序中的位置；右侧“常用语内容”显示所选条目，上方编辑“内容1”的标题及正文，下方编辑“内容2”的标题及正文；两组均可输入任意语言，修改自动保存在本机，也可分别复制。删除条目时清除其五向分配。旧版常用语保留原 ID、中文标题及内容，英文字段初始为空。

常用语浮层固定为 296 × 340 pt，使用 244 pt 的五向圆盘，位置与遥控器一致；沿用原生扇区点击层，图标、标题和扇区空白均可点击。标题为纯文字，隐藏重复的绑定小勾与标题装饰图标。圆盘使用中性灰，悬停或键盘聚焦时给予反馈；常用语标题保留单行显示及完整标题提示。底部保留单击、双击和返回 / 主页 / Esc 关闭提示，未分配与内容为空时在同一区域显示简短说明。支持浅色和深色。该设计方向参考 unslop by Damir Sokolovsky（@heydamir，CC BY 4.0）。

五向分配由常用语功能独立保存，在各遥控器和方案间共用，随配置备份导入导出。分配不会改写任何按键方案或全局按键。将“唤出常用语”固定动作绑定到任意可配置的普通按键手势后，该动作打开独立浮层；只在浮层显示期间接管遥控器输入，方向键和中间确认键分别触发各自分配的常用语：单击输入内容1正文，双击输入内容2正文。单击在双击判断窗口（0.3 秒）结束后输出，双击只输出内容2。浮层使用唤出时的常用语快照，成功输入后关闭；未分配或已删除的条目不输出，对应内容为空时提示并保持浮层打开。

返回、主页、菜单或 Esc 关闭浮层；失焦、切换应用、断连、休眠、更换遥控器、重新扫描或切换模式时取消浮层及待输出内容。打开浮层前会取消普通手势、组合动作和语音会话，唤出时仍按住的按键及关闭时未释放的按键会被消费到释放，避免触发原映射。浮层保持当前应用处于激活状态，关闭后将正文输入其文本焦点。“唤出常用语”不支持作为组合动作步骤。

语音设置统一沿用“遥控器麦克风 → 连接页所选接收设备 → 目标语音应用”的路径。用户在目标语音应用的麦克风设置中选择连接页上方的接收设备；仅当目标应用使用系统默认输入时，才需要在系统声音设置中选择同一设备。安装完成弹窗显示当前可用的接收设备名称，并提供“打开连接与语音”操作；设备不可用时要求先确认接收设备。发送 1 秒测试音用于观察目标语音应用中的麦克风输入电平，无需从扬声器听到声音；发送中及完成提示也指向该输入电平。

启动或按下语音键时，若缺少输入监控或辅助功能权限，提示提供“打开设置 → 权限”操作并持续显示到用户关闭或权限恢复；跳转不会清除提示。连接页在权限不足时也提供同一入口。点击后打开设置并滚动到权限分组；每次点击均可重新定位，普通进入设置不自动跳转。


操作通知包含独立 ID、级别、完整内容，以及适用时的修复入口。成功提示使用绿色勾选图标，约 3 秒消失；普通进度提示约 5 秒消失；错误使用红色图标，需处理的警告使用橙色图标，持续保留到用户关闭或对应故障解除。切换页面、复制内容或执行无关操作不会清除失败；多条通知可通过“另有 N 条提示”切换，关闭只影响当前一条。相同来源的重复故障更新为一条通知，每次成功提示有独立计时，不受上一条同文提示的计时影响。

通知默认显示三行摘要，可“展开详情”滚动阅读全文，也可选择文字或“复制详情”复制完整内容。导入、导出及恢复失败提供配置导入与导出入口，成功重试后清除对应失败。导入成功但仍有名称修复或失效引用时按需处理的警告保留。音频输出及测试音故障保留具体错误和“检查接收设备与麦克风组件”入口，跳转到“连接与语音”后可刷新设备、选择接收设备、安装或更新麦克风组件并发送测试音；取消或进入空闲不视为修复，仅重新进入实际音频输出状态后自动清除该故障。
