# 小米蓝牙遥控器 2（RC001-MS）

界面与诊断中的主型号为 `RC001-MS`，仍兼容 Device Information 返回的 `RC001`。

在「连接与语音 → 更换遥控器…」选择「小米蓝牙遥控器 2」。普通版使用独立的键位方案、Harness 绑定和全局按键配置，切回 2 Pro 后恢复其原配置。默认仍选择原有的 2 Pro，升级不自动切换型号。

RC001-MS 与 RC003-MS 共用 HID `2717:32B8`、13 项输入（含语音键）和 ATVV v1／16 kHz IMA ADPCM。语音键为 Keyboard F5，返回、菜单、主页、TV、自定义及音量 usage 复用小米适配器；语音仅允许按住说话。普通版使用独立的官方银灰色产品图，保留黑色顶部按键与橙色电源符号；2 Pro 保留银色顶部按键配图。按键页与连接页均按型号选择图片，点击区域、按压高亮和连线使用对应图片的几何数据，型号标题分别显示 RC001-MS 与 RC003-MS。素材来源及处理方式见 [素材说明](../assets/app/README.md)。

BLE 名称和 HID VID/PID 仅筛选候选设备；RC001-MS 档案必须读到 Device Information 型号 `RC001` 或 `RC001-MS`，RC003 档案必须读到 `RC003` 或 `RC003-MS`，才将按键标为已连接并启用映射。映射模式可在 BLE 型号确认前抑制当前型号的原生按键；型号依据物理 HID 设备的 ModelNumber，多候选且缺少该值时不抑制。型号确认前、型号不符或 BLE 断连时不启用 HID 输入，也不显示候选设备的电量；型号不符时语音连接统一显示“等待连接”，悬停可查看检测到的型号和当前选择的型号。语音仍须额外成功完成能力协商。RC003 型号和相同的 PnP ID 均不能代替 RC001 型号校验。

两款小米可以同时保持连接，在应用中切换当前控制的型号。BLE 对同名候选依次读取型号，跳过不符的设备；HID 监听与原生按键抑制读取各自 IORegistry 的 ModelNumber，完整映射与抑制仅作用于当前型号；未选中的小米仅抑制语音键（含 F5），其他按键保留原生行为。选择 Chromecast 时，两只小米也维持此语音键保护；原生模式或退出应用时全部恢复。只有一个物理候选且系统未提供该字段时，HID 监听才回退到 BLE 已确认型号；多个候选且字段缺失时不推断归属。当前仍只激活所选型号的键位方案与语音会话。

协议依据为 [SayAll 的 RC001 真机记录](https://github.com/HD838A/remote-mic-app/blob/64c382ac13c568e81277480048fcd29cc2e91ed1/TODO.md)、[型号目录](https://github.com/HD838A/remote-mic-app/blob/64c382ac13c568e81277480048fcd29cc2e91ed1/Sources/RemoteMic/RemoteDeviceProfile.swift)及其公开按键表；只采用设备事实，复用 RcHarness 现有实现。

本项目已覆盖 RC001 的型号隔离、13 个按键按下/释放、配置切换与持久化，并运行共享协议和音频测试。2026-11-08 已在 RC001 与 RC003 同时连接的测试环境确认：普通版型号识别、HID 连接、100% 电量读取及 ATVV v1／16 kHz／120 字节帧协商成功；首次验证原生按键抑制仅作用于 RC001 的事件服务。后续修复未选中小米语音键直通 macOS 引起提示音的问题，改为未选中设备仅保护语音 usage。新增回归覆盖同名候选逐只校验、无响应候选轮换及两个型号的 HID／原生按键隔离，258 项单元测试、HAL ASan/UBSan 和音频探针通过。

2026-11-08 语音键保护复验：选择 RC003-MS 时，系统读回 RC003 服务的 51 项完整抑制、RC001 服务的 3 项语音 usage 抑制；两者 F5 均映射为 0，RC001 的方向／音量键未被抑制。260 项单元测试、HAL ASan/UBSan 及音频探针通过；原生模式恢复、型号解析后由完整抑制缩小为语音保护、其他程序按键修改保留均有回归覆盖。

2026-11-08 小米蓝牙遥控器 2（RC001-MS）已通过真机验证。RC001-MS 更新为已实测状态，连接页及型号菜单移除待验收提示；诊断信息保留实测状态。
