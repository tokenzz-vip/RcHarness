# Google Chromecast Voice Remote（G9N9N）适配

在 macOS 蓝牙设置中配对遥控器，再到 RcHarness 的「连接与语音 → 更换遥控器…」选择 Google 蓝牙遥控器。按住返回与主页键进入配对模式。按键映射需要输入监控与辅助功能权限；语音还需要蓝牙权限，并在语音应用中选择 RcHarness 的回环输入设备。

## 识别与按键

设备身份集中在 `Core.swift` 的 `RemoteProfiles.googleG9N9N`：HID VID/PID 为 `18D1:9450`，蓝牙名称包括 `Chromecast Remote`；语音连接通过型号 `G9N9N` 或 BLE PnP ID（相同 VID/PID，厂商来源 1 或 2）校验。真机固件 26.2 的 Device Information 型号是 `A0`，厂商来源是 1；`A0` 本身不作为通过身份验证的依据，仍需精确匹配 PnP 身份。仅共享 ATVV 服务 UUID 不足以通过身份验证。

G9N9N 使用 Consumer Page（`0x0C`），按下为非零值，释放为零：

| 实体按键 | Usage |
| --- | --- |
| OK | `0x41` |
| 上／下／左／右 | `0x42`／`0x43`／`0x44`／`0x45` |
| 返回／主页 | `0x224`／`0x223` |
| 音量 +／−／静音 | `0xE9`／`0xEA`／`0xE2` |
| 电源／输入源 | `0x19E`／`0x89`（兼容旧映射 `0x189`） |
| YouTube／Netflix | `0x77`／`0x78` |
| 语音 | ATVV BLE START／STOP |

按键表已通过 2026-11-07 的 G9N9N 测试设备 固件 26.2 逐键采集核对；输入源实际是 `0x89`，修正了原先依据 [VibeMote 的实机 HID 映射](https://github.com/Tilkmilk/vibe-mote/blob/main/keys.py) 填写的 `0x189`，并保留旧别名。`0x42` 必须按型号解析，不能复用小米的返回键含义。电源、输入源和音量键如果已被电视配置为仅发红外，macOS 无法读取该红外信号，需要在原电视设置中调整；本应用只接收实际发送的蓝牙报告。

共有 15 项逻辑输入，支持普通按键的单击、双击、长按和实物图上的实时按压反馈。新建默认方案的静音／输入源／YouTube／Netflix 分别为静音、切换原生模式、复制、粘贴。已保存方案不被覆盖，新增键缺少配置时保持禁用。切换型号保留方案和 Harness；不受新型号支持的全局按键回退到电源键并保留原动作。

## 语音

复用 ATVV v1、16 kHz IMA ADPCM 和既有回环音频输出。Google 握手只声明 16 kHz ADPCM 与 hold-to-talk 能力；仍要求有效的能力回复，不将任意语音服务视为就绪。按协商的有界帧长缓冲和连续解码，不再固定要求小米的 120 字节；AUDIO_SYNC 重置预测器并清理未完成帧。线格式参考 [ATVVoice v1 实现](https://github.com/b0o/ATVVoice/blob/main/src/protocol/v10.rs) 与 [握手定义](https://github.com/b0o/ATVVoice/blob/main/src/protocol/mod.rs)。

Google 的语音键可以没有独立 HID 事件，因此从 BLE 流开始／结束生成去重的实体按键边沿，再进入同一权限检查、快捷键和尾音排空流程。断连、取消、切换型号会释放状态。只启用按住说话，松手停止收音；点按快捷键可编辑但不能启用点按模式。语音输出和虚拟麦克风协议不变。

若 BLE STOP 缺失，连续 2 秒没有音频包或单次语音达到 120 秒时主动关闭收音，补齐按键释放并排空尾音。超时后的迟到音频不会自行重新开启会话，需重新按语音键或收到显式启动通知。写命令失败会清除就绪状态并自动重连；电量特征发现失败仅显示电量未知，不中断核心连接。连接页直接显示异常原因。

## 验证边界

自动化覆盖全部 Consumer 按键及释放、型号隔离、PnP 身份、协商帧长与分包解码、语音边沿去重、原生按键抑制恢复、切换与保存、实物图点击区域。截图渲染可追加 `--remote-profile google-g9n9n`，仅在隔离的渲染设置中选择型号，不改变用户设置。

2026-11-07 已连接 G9N9N 测试设备（固件 26.2、硬件 PVT/MP、型号字符串 A0），逐一验证 14 个普通按键的按下／释放，均收到蓝牙报告，其中输入源重复按了两次，均成对释放。采集范围为按键 usage、按下／释放及 HID 描述符，不包含设备地址、序列号或音频；原始采集附件不随公开文档发布。

修正后已在应用中复测输入源按下／释放及语音键：PnP 身份确认成功、电量 100%、ATVV v1／16 kHz／160 字节帧协商成功；一次约 4.5 秒的按住说话收到 214 包、解码及输出 68,480 个样本，松手后停止采音并排空输出，快捷键正常释放，丢弃样本为 0。复测仅记录连接、按键和音频计数，不保存音频或识别文本。15 项实体输入均完成本次识别验收；244 项 Swift 单元测试通过。

首次配对、短按语音、快速重复、休眠重连、两种遥控器同时连接，以及退出后原生音量恢复仍需分别验收。仿制遥控器可能使用不同身份或不提供 ATVV 服务，本适配不据外壳型号自动放行。
